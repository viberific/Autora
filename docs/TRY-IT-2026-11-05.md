# Trying the app as a user (2026-11-05, 0.9.350)

What I did: ran the real server (`tests/e2e-harness.ts`, the repo's own harness) behind a **scripted stand-in model**, opened the
real page in headless Chromium, and used it like a person: asked for a song, a mug, a game, a spreadsheet, a letter, a flyer, a
photo canvas and a video project; edited the song by hand; opened the canvas chooser, Tools, Settings; looked at a phone.
Screenshots are in `docs/screenshots/try-2026-11-05/` (numbers below).

**Limits, stated plainly.**
- The model was scripted: I chose each tool call. So this tests how the app *reacts* to the agent, never what a real model would choose.
- Only the parts buildable in that container ran for real: the page, Panacea, **Music**, **3D**, the server tools. The Spectra (PDF),
  OpenCut (Video), GDevelop (Games), GenOffice (Pages/Sheets/Slides) and PhotoCraft (Photo) editors could not be built, because
  GitHub is blocked there. What a user sees *when an editor is missing* is real; what those editors do is untested.
- Sound, touch drags, and a real first-time user were not tested.

## What worked (so it is not lost)

- No console errors or failed requests on any normal path (Music, 3D, Panacea, Tools, Settings).
- Music's first screen is the best beginner start in the app: "Start a song: Beat / Chords / Bass / Melody, or just tell Autora"
  (07). Steps appear live while the agent works.
- The command logs built this session work live, in the real browser: the agent's four steps were logged, the person's drag
  across a lane became a `person_edit`, and the agent's revert of its own beat was **refused** because the person had edited
  after it ("1 FAILED", 03/04), while a revert with no person edit after it removed the Drums track from the window.
- 3D renders correctly (WebGL) and the model matches the tool calls (05).
- Games entry in the Panacea chooser says "Autora Games is not built into this server." in amber (11) rather than failing silently.

## Fixed in this change

1. **The "What do you want to do?" hint was drawn on top of every hosted window** (01, 03, 05, 06). It showed whenever the native
   canvas was empty, ignoring open Music/3D/PDF windows, and covered the lanes, the clip the person just made, and 3D's Size &
   position panel. First fixed by hiding it when a window was open (04, 07, 10); then **removed entirely at the person's
   direction**: a blank canvas shows nothing, controls appear when the work needs them (`PanaceaWindow.tsx`, `.pa-empty` CSS, and
   the two UI tests that used it as a "ready" signal now wait on the canvas). Finding 5 below (the hint's copy) is moot.
2. **The new tools had no friendly status text** (cards read "tool 1ms"). Added to `src/lib/activity.ts` and `src/lib/thought.ts`
   (`*_history`, `game_play`). They were also missing from the Tools page's lists of tool names; **at the person's direction those
   lists are removed** (Panacea is the one tool; names of tool functions are not for the person). The on/off switches stay.
   Settings has the same per-group list of tool names (`Settings.tsx`, `.tool-names`): not touched, waiting for a decision.

## Not fixed: for a decision, most important first

3. **Phone: every hosted window is a postage stamp.** Music is ~220 px wide in the corner of a mostly empty screen (09, 10); the
   tool column floats over it. A phone should open the window full-screen, or at least large. (Unverified for the other windows.)
4. **When an editor is not installed the failure is ugly and slow.** PDF and Video windows show a raw Node error with a server
   file path (`ENOENT ... /home/user/Autora/dist/spectra-editor/index.html`) while the header still says "Saved as you go" (13, 14).
   `video_open` then waits on the missing editor for up to ~90 s showing only "RUNNING 12s Using video open". Tools whose
   editor is missing (Games, Photo, Office) are silently left out of the offered list, so the agent is told only
   `"game_open" exists but its group is not available right now` (`server.ts`, "exists but its group") and cannot tell the person
   why (not installed vs switched off on the Tools page); the card says "1 FAILED" with no reason (12). Suggest: one health check at
   start that says which editors are missing, surfaced on the System page and in the agent's briefing; windows that fail to load say so plainly.
5. ~~The blank canvas tells the person to "Use the centered Ask Autora bar"~~ (08): removed with the hint. `docs/PANACEA.md` still
   speaks of a "centered Ask Autora entry"; check whether that exists in any layout.
6. **Enter does not send; Ctrl/Cmd+Enter does** (`App.tsx`, the composer). Deliberate, but a first-time user will type, press Enter,
   and get a newline. The send arrow is lit but easy to miss.
7. **3D's first call took 21 s** (two shapes; engine start) with only "2 steps … 21s" shown.
8. **Collapsed tool cards show only the first argument** ("revert", "name=Space Dodger"), so the *reason* a call was refused is
   hidden unless expanded. For the music authority rule the person sees "1 FAILED" and has to read the agent's words to learn why.
9. **Music window is cramped**: the piano roll and drum grid are clipped at the window's bottom edge (02, 03); the floating
   selection toolbar overlaps the lanes' right edge.

## Not tried

Photo, Office editors, PDF editor, Video editor, GDevelop (none buildable), `game_play` on a real game, real models, audio, touch
gestures, desktop Safari/Firefox, the System and Usage pages. The first thing to do with a proper install is the five-minute path in
`intent/2026-11-05-first-game-in-five-minutes.md`.
